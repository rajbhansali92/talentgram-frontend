## 3. Delivery ≠ generation — does constructing a URL bill?

**No.** Every helper above is a `cloudinary.utils.cloudinary_url(...)` **string builder** — it
does local string formatting and makes **no API call**. Cloudinary bills a transformation only
when a client actually issues the **first GET** for that exact derived URL; Cloudinary then
generates the derived asset (one transformation charge), stores it, and serves the cache for
every subsequent request (bandwidth only). Traced per token:

| Token | Where it can still appear | Generated in production now? |
|---|---|---|
| **video poster** (`c_fill,h_338,q_auto,w_600`) | T1 — 1 per video, persisted | Only for a video whose poster was never persisted (legacy) **or** a brand-new upload. **0 observed since P5** |
| **`w_200` thumbnail** | T4 — 1 per image, persisted at `/complete` | Only on a new image upload. **0 observed since P5** |
| **`w_400` roster thumbnail** | T3 — 1 per cover image, persisted | Only on cover-image change / new upload. **0 observed since P5** |
| **HEIC `f_auto`** | T5 | Only when a stored HEIC image is rendered and its `f_auto` variant does not yet exist. Rare; **0 observed since P5** |
| **HEVC / non-web `f_mp4` compat** | T2 | Only on upload of a genuinely non-web video. **0 observed since P5** |
| **any remaining `f_auto`** | T5 (HEIC) + T3/T4 base | web-safe images now get the **canonical URL, zero `f_auto`** (`IMAGE_URL` test asserts this) |
| **any remaining `q_auto`** | T1/T3/T4 only (small, sized) | not on full-res delivery any more |
| **`dpr_auto`** | **nowhere** — removed from `cloudinary_url_for` (test `test_cloudinary_url_for_image_has_no_dpr_auto`) | never |
| **`c_fill`** | T1/T3/T4 (sized thumbs/poster) | as above — 1 per media item, once |
| **`c_limit`** | **nowhere in current code** (was the 1200/1600 presets + 720p chain) | never |
| **`vc_auto`** | **nowhere** — `stream_video_url` no longer emits it (test `test_stream_video_url_no_longer_transcodes`) | never |
| **`f_mp4`** | **only** T2 (`compat_video_delivery_url`) — test `test_compat_delivery_is_the_only_video_f_mp4_path` | only rare compat uploads |
| **`f_avif`** | **nowhere** — no helper hard-codes it (test `test_no_helper_emits_full_res_avif`); `IMAGE_URL` serves canonical | never (this was the biggest pre-P5 line) |
| **`fl_attachment`** | T6 — pure delivery flag on a canonical asset | generates **no derived asset**, not billed (P5) |

**Net:** the current app emits at most **4 billable transformation strings per media item, once
each, then cached forever** (T1 poster, T3/T4 thumbs, T2 compat when applicable). Web-safe image
*delivery* — historically the entire `extra_avif_mp_encoding` line — now emits **zero**
transformations.

### The 468 persisted historical derivatives — investigated

These are derived assets whose **exact URL is persisted in a live `media[]` field**
(`url` / `poster_url` / `thumbnail_url` / `original_url` / `compat_delivery_url` / `video_url` /
`secure_url`), matched per `(normalised_parent, transformation_family)`. Family breakdown:

| Family | Count | What it is |
|---|--:|---|
| `c_fill,dpr_auto,f_auto,q_auto,w_N` | 370 | old roster/thumb URLs stored as `thumbnail_url` (pre-P5, with `dpr_auto`) |
| `c_fill,dpr_auto,h_N,w_N/q_auto/jpg` | 40 | old poster URLs stored as `poster_url` |
| `c_limit,h_N,w_N/q_auto,vc_auto` | 39 | old 720p video-delivery URLs stored as `url` |
| `w_N,h_N,c_limit,q_auto,vc_auto,f_mpN` + variants | ~19 | old eager 720p+mp4 URLs stored as `url` |

**Why they are PROTECTED:** deleting the derived asset while its URL is still the stored `url` /
`poster_url` / `thumbnail_url` would **break that media item's display** — the client would
request a now-404 derivative. The transformation would silently regenerate on next view (cost +
latency), or 404 if generation is restricted.

**Prerequisite migration to make them removable (P11 candidate, additive, reversible):**
1. For each of the 468, compute the **canonical replacement URL** — for a stored `thumbnail_url`,
   `media_url(public_id, preset)`; for a stored `poster_url`, `video_poster_url(public_id)`; for a
   stored video `url`, the canonical original (or `compat_video_delivery_url` if
   `needs_compat_delivery`).
2. **Verify** the replacement resolves (HEAD, read-only) and points at a live asset.
3. In one guarded, audited pass, **update the stored field** to the canonical URL (a MongoDB
   write — so a *new phase*, not P10/P9). Keep the old value in an `original_url_pre_migration`
   field for rollback.
4. Only **after** the 468 media items no longer reference the old derivative may P9 delete it —
   subject to the same per-asset revalidation.
- **Do NOT rewrite any stored URL in P10.** This is a scoped future phase with its own approval.
